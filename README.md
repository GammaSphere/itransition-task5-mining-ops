# Weyland-Yutani Mining Ops: Task 5

A data source and an analytics dashboard for the daily output of Weyland-Yutani mines.

- **Part I, generator:** a Google Spreadsheet built only from cell formulas, no script. You set the parameters and it produces realistic daily output per mine, with a live chart.
- **Part II, dashboard:** a web app that reads the spreadsheet live. It computes statistics, runs four anomaly tests with adjustable parameters, draws line, bar and stacked charts with outliers and trendlines, and exports a detailed PDF report.

## Part I: the generator spreadsheet

### Parameters (sheet `Generator`)

| Row | Parameter | Notes |
| --- | --- | --- |
| Range | Start date, days count | 1 to 730 days; the end date, total, average and peak are calculated live |
| Mines | up to 8 names | type a name to add a mine, clear it to remove one; every mine becomes a column and a chart line |
| Random | distribution, its parameters, smoothing, correlation, seed | **Normal** (Mean, Deviation), **Uniform** (Min, Max), **Log-normal** (Mean, Deviation), **Triangular** (Min, Mode, Max). The parameter headers change with the distribution, and a hint line shows the derived values |
| Daily output | factor per weekday | e.g. Saturday 0.8, Sunday 0.4 (output reduced by 60 %) |
| Daily growth | % per day, compound or linear | the overall trend |
| Events | day, duration, factor, probability, mines, shape | up to 8 spikes or drops; **Mines** (exact number of affected mines) overrides **Probability**; **Bell** gives a bell-shaped anomaly, **Flat** a step; the affected mines are listed live |

### Why the data looks realistic

Output is multiplicative, as in a real operation:

```
output(m, t) = max(0, F^-1(Phi(z[m,t]))) x weekday(t) x trend(t) x PRODUCT_e (1 + (Factor_e - 1) x w_e(t) x hit[e,m])
z[m,t]       = rho x z[m,t-1] + sqrt(1 - rho^2) x (sqrt(c) x common[t] + sqrt(1 - c) x own[m,t])
```

- **Smoothing** is an AR(1) process on a standard normal variable, mapped through the chosen distribution (a Gaussian copula). Consecutive days are correlated (`rho`) while each day still follows the chosen distribution exactly. It is not white noise.
- **Correlation** mixes a shock shared by all mines (`c`), so mines move together on bad days.
- **Bell events** use a Gaussian weight whose full width at half maximum equals the duration, so effects ramp up and fade out.
- **Seeded randomness.** The random numbers are a deterministic hash of (seed, day, mine), `MOD(SIN(...) x 43758.5453, 1)`, not `RAND()`. The data only changes when a parameter changes, and changing the seed gives a new realisation.

### How the sheet is built

| Sheet | Content |
| --- | --- |
| `Generator` | parameters and charts (the only sheet you edit) |
| `Data` | the data source: `Date` and one column per mine and `Total`, one `VSTACK`/`HSTACK`/`FILTER` spill formula |
| `Engine` | one array formula per column (`MAP`, `SCAN`, `BYROW`) and one row per day: calendar, noise, base output, event weights, event factors, output |
| `Model` | distribution constants and the event-to-mine map (`MAKEARRAY`) |
| `Guide` | how to use it and the model |

The workbook is generated by [`generator/build_sheet.py`](generator/build_sheet.py) and imported into Google Sheets (File, then Import). [`generator/model.py`](generator/model.py) is a Python reference implementation of the same formulas. The values Google Sheets computed match it to the cent (for example LV-426 on 2099-11-02).

## Part II: the dashboard ([`dashboard/`](dashboard/))

**Data access.** The browser reads the `Data` sheet, the event table and the parameters through the Google Visualization API (`/gviz/tq?tqx=out:json`). That endpoint returns raw numbers, so the spreadsheet's locale doesn't matter. If the browser blocks the call, the dashboard goes through a same-origin Netlify proxy (`/gsheets/*`). If the sheet can't be read at all, it falls back to a bundled offline sample and says so in a banner. **Refresh data** re-reads the sheet, and **Auto-refresh** polls every 30 s and notes when the data changed. **Use another spreadsheet** connects a copy.

**Statistics** for each mine and the total: mean, standard deviation (n - 1), median, quartiles (type 7 / `QUARTILE.INC`), IQR, min, max.

**Anomaly detection.** Every parameter is adjustable in the side panel:

- *What the tests look at.* By default each series is fitted with a robust regression of `log(output)` on a polynomial trend and day-of-week dummies, using Tukey bisquare IRLS so anomalous days barely influence the fit. The tests then use each day's relative deviation from this expected level, so growth and the weekly cycle aren't flagged. Turn both options off to test raw values.
- **IQR rule:** outside `[Q1 - k IQR, Q3 + k IQR]` (k adjustable).
- **Z-score:** `|z|` above a threshold, optionally robust (median and MAD).
- **Distance from moving average:** window, % and trailing or centered. The tested day is excluded from its own average.
- **Grubbs' test:** significance alpha and up to `r` outliers (Rosner's generalized ESD). With `r = 1` it is the classic test. With `r > 1` a cluster of anomalies can't mask itself.
- A day is an **anomaly** when at least N of the 4 tests agree (N adjustable). Consecutive anomalous days form an **episode**. Each episode is matched against the events configured in the generator, and the dashboard reports how many configured event hits were detected.

**Charts:** line, bar, stacked bars or stacked area, with anomalies marked (up / down triangles) and least-squares polynomial trendlines of degree 1 to 4. There is also a per-series view with the expected level, the moving average and the IQR normal band, a test-by-day detection matrix, a box plot per mine and the estimated weekly pattern.

**PDF report** (Download PDF report): cover with key figures and findings, the output charts as configured, the statistics table, the detection method and parameters, flag counts and the episode table, a detail page per series, and a separate section for every anomaly episode with a zoomed chart, a day-by-day table and the matching generator event. An appendix lists the generator settings and method notes.

## Run it locally

```bash
# generator
python -m venv .venv && .venv/Scripts/pip install -r generator/requirements.txt   # bin/ on macOS/Linux
.venv/Scripts/python generator/build_sheet.py      # -> generator/WY_Mining_Ops_Simulator.xlsx
.venv/Scripts/python generator/model.py            # -> dashboard/public/sample-data.json (offline sample)

# dashboard
cd dashboard
npm install
npm run dev          # http://localhost:5173 (?source=sample for the offline sample, ?sheet=<id or link> for another sheet)
npm test             # statistics and detection tests (reference values from SciPy / NumPy)
npm run e2e          # browser smoke test: screenshots and a PDF download (needs Chrome or Playwright's Chromium)
npm run build
```

Deploy: `netlify deploy --prod --dir dashboard/dist` (the site is linked; `netlify.toml` holds the build settings).
